# 智慧製造排程模擬器
## Max-Heap × Queue 在混線生產（Mixed-model Production）中的應用

---

## 一、作業題目背景

精密加工廠接到一張緊急的「混線生產」訂單，必須用同一台最高階的 5 軸 CNC 機台共 10 台、10 條生產線，並生產一批不同規格的航太零件共 50 件（產品型號：P1, P2, … P10），派工生產共 500 件。

### 核心限制條件

| 條件 | 說明 |
|------|------|
| 冷卻週期 n | = 3（每做完一件 P? 零件，該型號的專用刀具需強制冷卻 3 個 time slot）|
| 換刀彈性 | 冷卻期間可自動換刀，改做「非 P? 型號」的零件 |
| 閒置 Idle | 若無其他型號可做，機台進入空轉等待 |
| 理論最少耗時 | 50 單位（無冷卻限制時） |

---

## 二、資料結構角色說明

### Max-Heap（最大堆積）— 智慧決策大腦

Max-Heap 中儲存的是每個產品型號目前**待生產的剩餘件數**。

```
Max-Heap 節點格式：(-剩餘件數, 產品型號)
（以負值模擬最大堆積：Python heapq 為 min-heap，取負值即得最大優先）
```

**為何用「剩餘件數最多」優先？**

這是 Greedy 貪心策略——永遠先消化數量最多的型號，可以最大化平衡每個型號的執行間距，從而將被迫 Idle 的機率降到最低。

**Heap 動態變化過程（舉例）：**

初始頻率統計後，建立堆積：

```
              P1×8
           /        \
        P3×6        P2×5
       /    \
    P7×4   P5×3
```

Step 1：取出 P1×8 執行，P1 剩餘 7，進入冷卻 Queue。
最後一個節點 P5×3 移到頂端後執行 **Heapify Down**：

```
              P3×6          ← P5×3 下沉後，P3×6 浮頂
           /        \
        P5×3        P2×5
       /
    P7×4
```

Step 4（T=4）：P1 冷卻解凍，count=7 推回 Heap，執行 **Heapify Up**：

```
              P1×7          ← 重新登頂
           /        \
        P3×6        P2×5
       /    \
    P7×4   P5×3
```

### Queue（佇列）— 冷卻等待輸送帶

Queue 採用 FIFO（先進先出）結構，儲存格式如下：

```
Queue 節點：(可解凍時間, 產品型號, 剩餘件數)
可解凍時間 = 當前時間 + n + 1 = 當前時間 + 4
```

Queue 就像工廠裡的實體輸送帶：剛生產完的刀具依序排隊冷卻，時間到了才能重新上線。

## 三、每個 Time Slot 的完整執行步驟

```
┌─────────────────────────────────────────────────┐
│  每個 Time Slot 的演算法流程                      │
│                                                 │
│  Step 1：Queue 解凍檢查                          │
│    └── 若 Queue.front 的解凍時間 ≤ 當前時間       │
│        → 彈出，推入 Heap（可能多筆同時解凍）       │
│                                                 │
│  Step 2：Heap 決策                               │
│    ├── Heap 非空 → 取出頂端 (count, type)         │
│    │   count -= 1，執行任務                       │
│    │   若 count > 0 → 推入 Queue 冷卻             │
│    └── Heap 為空 → Idle（空轉等待）               │
│                                                 │
│  Step 3：時間推進 time += 1                      │
└─────────────────────────────────────────────────┘
```

## 四、關鍵數學公式

### 理論最少耗時（無冷卻限制）

$$T_{min} = \text{總件數} = 50 \text{ 單位}$$

### 實際最少耗時（含冷卻限制）

$$T_{actual} = \max\left(\text{總件數},\; (f_{max} - 1) \times (n + 1) + k\right)$$

其中：
- $f_{max}$ = 出現頻率最高的型號件數
- $n$ = 冷卻週期 = 3
- $k$ = 出現最高頻率的型號數量

### 稼動率

$$\text{稼動率} = \frac{T_{actual} - \text{Idle 次數}}{T_{actual}} \times 100\%$$

## 六、智慧製造實際對應關係

```
演算法元件          工廠實體對應
────────────────────────────────────────
Max-Heap 頂端    ↔  最緊急、最多待產的型號
Heapify Down     ↔  決策系統重新評估優先順序
Heapify Up       ↔  冷卻完成型號重新搶奪派工資源
Queue FIFO       ↔  刀具冷卻台的實體排隊順序
解凍條件         ↔  感測器確認刀具溫度回歸正常
Idle             ↔  機台空轉警報（稼動率損失）
```

## 七、演算法複雜度分析

| 操作 | 時間複雜度 | 說明 |
|------|-----------|------|
| Heap Push | O(log k) | k = 目前 Heap 大小（≤ 產品種類數）|
| Heap Pop | O(log k) | 取出最高頻率型號 |
| Queue Enqueue | O(1) | FIFO 尾端插入 |
| Queue Dequeue | O(1) | FIFO 頭端取出 |
| 整體模擬 | O(N log k) | N = 總件數，k = 產品種類數 |

由於產品種類 k 最多 50 種，log k ≈ 6，整體效率極高，即使 N=500 件也能在毫秒內完成排程。

---

## 八、結論

Max-Heap 保證「最需要被生產的型號永遠優先」，Queue 保證「冷卻順序合法且可追蹤」。兩者相輔相成，使得混線生產的排程問題從 O(N²) 的暴力搜尋降至 O(N log k) 的高效貪心解，是工業 4.0 智慧排程的核心演算法基礎。
