# 自助洗衣店排程系統
## Max-Heap × Queue 在共享資源分配中的應用

---

## 一、生活場景背景

自助洗衣店擁有數台洗衣機（有限資源），每天有多位客人帶著不同重量、不同緊急程度的衣物前來等候。若照先來先服務（FIFO）安排，早到的客人等很久，晚到但衣物量多且緊急的客人卻在後面乾等，導致整體等待時間拉長、機器使用效率低落。

**核心問題：在有限洗衣機台下，如何安排洗衣順序，讓整體完成效率最高？**

這個問題本質上與 CNC 機台的混線生產排程完全相同，只是場景換到了生活中的洗衣店。

### 對應製造業題目的類比

| 智慧製造 | 自助洗衣店 |
|---------|-----------|
| CNC 機台 | 洗衣機 |
| 產品型號 P? | 客人的衣物（姓名 + 衣物種類）|
| 刀具冷卻週期 | 洗衣機清洗滾筒週期 |
| 剩餘件數 | 衣物優先值（等待時間 × 衣物重量）|
| 機台 Idle 空轉 | 洗衣機空著但滾筒還在自清中 |

---

## 二、優先值設計邏輯

每位客人的衣物優先值（Priority Score）由兩個因子組成：

```
優先值 = 等待時間（分鐘）× 2 + 衣物重量（kg）× 5
```

| 因子 | 說明 | 權重設計理由 |
|------|------|------------|
| 等待時間 | 客人已在門口等候的分鐘數（5~35 分鐘）| 避免長時間等待造成抱怨，×2 加權 |
| 衣物重量 | 衣物總重量（kg），重量越大說明需求越迫切 | 洗大量衣物通常有急迫原因，×5 加權 |

優先值越高 → 在 Max-Heap 中越靠近頂端 → 洗衣機越優先服務這位客人。

---

## 三、資料結構角色說明

### Max-Heap（最大堆積）— 機台排班決策大腦

儲存所有「目前排隊等候」的客人，依優先值排序。

```
Max-Heap 節點格式：{id, name, type, waitMin, kg, priority}
```

**衣物種類與特性：**

| 衣物種類 | 特性說明 |
|---------|---------|
| 床單被套 | 體積大、重量重，通常是整理家務的急迫需求 |
| 厚外套 | 季節換裝，時間敏感 |
| 嬰兒衣物 | 清潔要求高，家長通常最急切 |
| 棉質衣物 | 日常衣物，優先值依等待時間決定 |
| 絲綢禮服 | 特殊場合，時間壓力高 |

**Heap 動態變化過程（舉例）：**

初始 Heap（3 位客人）：

```
          陳媽媽-床單被套(優先值 92)
            /                    \
  小明-棉質衣物(63)          阿花-牛仔褲(41)
```

陳媽媽的衣物進洗衣機後，Heapify Down：

```
          小明-棉質衣物(63)
               |
          阿花-牛仔褲(41)
```

大雄帶著 10kg 厚外套（等待 28 分鐘，優先值 56+50=106）抵達 → Heapify Up：

```
          大雄-厚外套(106)    ← 插隊至頂
           /              \
  小明-棉質衣物(63)   阿花-牛仔褲(41)
```

### Queue（佇列）— 洗衣機清洗滾筒冷卻帶

每台洗衣機在完成一批衣物後，需進行**滾筒自清潔程序**（除去殘留洗劑、消毒），才能接受下一位客人的衣物。

```
Queue 節點：(可接受下批衣物時間, 'mach', 客人資料)
可接受時間 = 當前時間 + 清洗冷卻週期 + 1
```

這個 Queue 的 FIFO 結構反映了洗衣機的物理清潔順序：先完成洗衣的機器先進行自清，先自清完成的機器先重新開放使用。

## 四、每個 Time Slot 的完整執行步驟

```
┌──────────────────────────────────────────────────────┐
│  洗衣機排程 — 每個 Time Slot 執行流程                 │
│                                                      │
│  Step 1：機台自清完成檢查（Queue → Heap）             │
│    └── 若 Queue.front 的可用時間 ≤ 當前時間           │
│        → 洗衣機自清完成，重新開放                     │
│        → 推入 Heap，參與下一輪接客競爭                │
│                                                      │
│  Step 2：服務決策（Heap 頂端 → 洗衣機）               │
│    ├── Heap 非空 → 取出優先值最高的客人               │
│    │   → 安排進入洗衣機                              │
│    │   → 洗衣機進入自清 Queue                        │
│    └── Heap 為空 → Idle（等待機台自清完成）           │
│                                                      │
│  Step 3：time += 1                                   │
└──────────────────────────────────────────────────────┘
```

## 五、關鍵設計邏輯

### 優先值 vs. 先來先到

| 服務策略 | 公平性 | 效率 | 客訴風險 |
|---------|--------|------|---------|
| FIFO（先來先服務）| 高（到達順序公平）| 低（不考慮資源最佳化）| 中（急件客人不滿）|
| Max-Heap（優先值）| 中（急件優先）| 高（整體等待時間最短）| 低（急件客人最滿）|
| 純隨機 | 低 | 低 | 高 |

Max-Heap 策略在「整體平均等待時間最短」與「急件客人優先」兩個目標間取得平衡。

### 為何自清要用 FIFO Queue？

洗衣機的自清程序是機器硬體固定的：
- 洗衣機 A 在 T=2 完成 → T=5 才可再用（自清 3 分鐘）
- 洗衣機 B 在 T=3 完成 → T=6 才可再用（自清 3 分鐘）

Queue 精確追蹤每台機器的可用時間，避免系統誤將還在自清的機台分配給客人。

### Idle 的現實含義

若所有洗衣機都在自清 Queue 中尚未完成，而仍有客人在等候（Heap 非空），那表示：

- **機台數量不足**：應考慮增購設備
- **自清週期過長**：應考慮升級自清功能更快的機型

Idle 率是店主決定是否擴充設備的重要指標。

## 六、模擬器功能說明

### 可調整參數

| 參數 | 預設值 | 說明 |
|------|--------|------|
| 客人數 | 12 | 本日進入洗衣店的客人總數 |
| 洗衣機台數 | 3 | 店內洗衣機總台數 |
| 清洗冷卻 | 2 | 每台洗衣機自清所需時間單位 |

### 顯示面板

| 面板 | 內容說明 |
|------|---------|
| Max-Heap 候洗佇列 | 所有等待中的客人，依優先值排序，紫框標示頂端 |
| 清洗冷卻 Queue | 顯示自清中的機台與預計完成時間，綠框代表已完成 |
| 已完成 | 按完成時間反序顯示已服務的客人清單 |
| 機台狀態格 | 直覺顯示每台洗衣機目前的狀態（洗衣中/冷卻中/待機）|

### 統計輸出

- 總客人數 / 已完成服務數
- 機台閒置次數（Idle）
- 整體機台稼動率（%）

## 七、實際洗衣店對應關係

```
演算法元件          自助洗衣店實體對應
──────────────────────────────────────────────
Max-Heap 頂端    ↔  當下最急迫（等最久且衣物最重）的客人
Heap Push        ↔  新客人抵達，店員登錄等待資料
Heapify Up       ↔  急件客人自動插隊到候洗佇列前面
Heapify Down     ↔  服務完最高優先後，次高客人浮頂
Queue FIFO       ↔  洗衣機完成洗衣後進入自清的先後順序
解凍條件         ↔  機台自清程序完成、系統確認可再用
Idle             ↔  機台空著但全部在自清中（浪費）
```

## 八、與智慧製造題目的核心共通點

自助洗衣店排程問題與 CNC 混線生產排程問題，在資料結構層面完全同構：

| 比較面向 | 智慧製造 | 洗衣店 |
|---------|---------|--------|
| 資源 | CNC 機台 | 洗衣機 |
| 任務 | 生產航太零件 | 洗衣物 |
| 優先依據 | 剩餘件數（Greedy）| 等待時間 × 衣物重量 |
| 冷卻意義 | 刀具溫度冷卻 | 滾筒自清潔 |
| Idle 含義 | 機台空轉損失 | 機台無法接客的浪費 |
| 最佳化目標 | 最小化總耗時 | 最小化平均等待時間 |

唯一差異在於「優先值的計算方式」——製造業使用型號剩餘件數，洗衣店使用複合式優先公式。這體現了 Max-Heap 的高度通用性：**只要能為任務定義一個優先值，Max-Heap 就能自動完成最優排程決策。**

## 九、結論

自助洗衣店排程問題是 Max-Heap + Queue 最貼近日常生活的應用場景之一。它說明了這套演算法不是工業 4.0 的專利，而是任何「有限資源 + 多任務競爭 + 冷卻週期」問題的通用解法。從急診室到外送平台，從 CNC 工廠到街角洗衣店，Max-Heap 永遠知道「現在最重要的事是什麼」，Queue 永遠確保「物理世界的冷卻順序被正確遵守」。
